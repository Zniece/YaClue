# YaClue v0.1.0-alpha.3

Release date: 2026-09-11.

Alpha 3 freezes the current pre-semantic-core application as the correctness
and performance baseline for the upcoming large architectural rewrite. It is
an evaluation release, not a stable API or app-store release.

## Frozen product capabilities

- One-window expression input and structured product output;
- direct two-argument `Limit(expression, at)` syntax;
- direct three-argument `Taylor(expression, center, degree)` syntax;
- inside-out lowering for the supported composition chain;
- equation operands containing supported Taylor and integral compositions;
- generated arbitrary-constant identity propagation across compositions;
- development-only JSON Lines stdin/stdout test interface;
- 27 non-trivial frontend examples audited as supported.

Representative regression:

```text
y' == Integrate(x) Taylor(Exp(x), 0, 2)
```

The frozen implementation lowers Taylor first, integrates the polynomial, and
then solves the equation while preserving `x` as a parameter and the generated
integration constant as an arbitrary constant.

## Validation baseline

Command:

```text
./scripts/test-gate.sh release
```

Result: passed. Wall time: 606.54 seconds.

The gate includes workspace formatting, Clippy with warnings denied, frontend
syntax validation, all workspace unit/integration tests and Rust doc tests.
External C++ Yacas adapter tests remain intentionally ignored unless
`YACAS_BIN` is supplied.

## Performance baseline

Command:

```text
cargo run -q -p processing --release --example semantic_bench
```

Persistent-session medians, 21 samples after 5 warmups:

| Case | Median |
|---|---:|
| Direct `Gamma(1/x)` | 5.717 ms |
| Standard intrinsic definition | 5.866 ms |
| Equivalent intrinsic form | 11.041 ms |
| Bounded recognition miss | 83 ns |
| Five-derivative composition chain | 324.089 ms |

Measurement host:

- Apple M5, arm64;
- macOS 26.6.2 (25G83);
- rustc 1.97.1;
- cargo 1.97.1.

These numbers are a comparison baseline, not a cross-machine performance
promise. Future measurements should use the same Release benchmark protocol
and compare parse count, CAS round trips, allocations and peak live objects in
addition to elapsed time.

## Packages

The prerelease workflow builds:

- Linux x86_64: deb, AppImage and rpm;
- macOS Apple Silicon: app and dmg;
- Windows x86_64: NSIS installer;
- Android arm64: universal debug APK.

The Android APK uses the development/test signature and can be installed
directly for evaluation. It is not suitable for an app store. A persistent
release signing key is intentionally not stored in the repository.

iOS is not part of this freeze: the repository does not yet contain an iOS
shell or Apple mobile signing configuration.
