## 当前未提供的旧入口

- `Factorize`：使用标准脚本的 `Factor` 或具体多项式接口。
- `ExtraInfo'Set`：旧对象标签接口，当前表达式模型未公开。
- `MathSinh`、`MathCosh`、`MathTanh` 及三个 `MathArc*` 双曲函数：旧底层数值入口；使用标准脚本的用户函数。
- `IsPromptShown`、`ReadCmdLineString`：旧交互式控制台钩子；当前文本由 Rust 宿主传入。
- `GetTime`：旧解释器计时入口；使用 Rust benchmark 或宿主计时。

这些条目已从当前函数正文移除，只在本页保留迁移线索；它们不属于当前必须接口。

## 包装载后出现的名称

- 图运算符 `->` 随图包声明。
- `OrthoPoly`、`OrthoPolySum` 是正交多项式包的内部助手。
- `GetError` 位于 I/O 错误脚本中，但没有单独的 `.def` 登记。

这类名称不能单独证明启动失败。应先调用该包公开登记的入口，再判断包内函数。

## “可发现”不等于“已验证”

结构审计只能证明名称由核心或脚本库登记。函数的参数语义和结果仍应由对应 `.yts`、Rust 测试或产品回归用例确认。文档状态采用以下层级：

1. **语言核心**：由 Rust 核心测试覆盖；
2. **标准脚本入口**：由 `.def` 暴露，并应有 `.yts` 行为测试；
3. **包内助手**：只保证所属公开入口所需的行为；
4. **历史条目**：仅供迁移参考，不构成兼容承诺。

后续按参考手册模块核验时，应把测试覆盖和已知边界补到具体页面，而不是生成一份脱离实现的静态“全部支持”列表。
