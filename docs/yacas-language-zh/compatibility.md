# 兼容性与稳定性

Yacas 延续上游规则语言和标准脚本的基本模型，并由本项目维护 Rust 引擎、脚本修订、资源边界和产品接口。兼容性方针支持脚本维护与实现演进。

## 稳定层级

| 层级 | 稳定承诺 |
|---|---|
| 语言语法与求值模型 | 最高；变更必须更新语言测试和规范 |
| 标准脚本公共入口 | 保持已有可验证入口，扩展优先使用新规则或新版入口 |
| 核心命令 | 保证标准脚本所需语义；内部 Rust 组织可调整 |
| Rust 底层模块 | 仓库内部接口，后续由高层 facade 封装 |
| processing 与 GUI | 建立在 Yacas 脚本语言之上的产品 API |

## 行为裁决顺序

1. 本项目明确记录并测试的行为；
2. [语言规范](language-spec.md)；
3. Rust 核心与标准脚本的现行实现；
4. 详细参考手册中的迁移说明。

具有完整输入和稳定复现、且违反现行契约的问题构成兼容性缺陷。旧实现输出可作为调查证据。

## 允许的改进

兼容方针涵盖错误、非终止和状态泄漏修复，资源上限、数值表示、错误分类与规则分派改进，以及假设、追踪、宿主接口和信息更完整的新入口。

有意改变可观察结果时，应记录触发条件、旧行为、新行为和理由，并添加回归测试。

## 标准脚本维护

标准脚本保留公开函数和可运行规则，新算法优先放入来源清晰的扩展包。测试定义受维护的行为，并在重构时保护无关脚本。

Rust 核心与标准脚本以语言命令为边界。可维护性、实测性能、规则可扩展性和许可共同决定脚本算法是否迁入 Rust。

## 参考资料与归属

编程指南、函数参考和算法说明最初来自 Yacas 文档，许可和贡献者信息保留在本目录。这些资料现在是本项目的维护基线，测试与产品契约标识受支持的功能。仓库内 `oracle` 为兼容性调查提供可选证据；Rust 实现承担构建、测试和发布。
