# 兼容性与稳定性

Yacas 延续 Yacas 规则语言和标准脚本的基本模型，但当前项目拥有自己的 Rust 引擎、脚本修订、资源边界和产品接口。兼容性的目的是让脚本可维护地运行，而不是冻结历史实现细节。

## 稳定层级

| 层级 | 稳定承诺 |
|---|---|
| 语言语法与求值模型 | 最高；变更必须更新语言测试和规范 |
| 标准脚本公共入口 | 保持已有可验证入口，扩展优先使用新规则或新版入口 |
| 核心命令 | 保证标准脚本所需语义；内部 Rust 组织可调整 |
| Rust 底层模块 | 主要供仓库内部使用，尚未承诺稳定 facade |
| processing 与 GUI | 产品 API，不属于 Yacas 脚本语言标准 |

## 行为裁决顺序

1. 本项目明确记录并测试的行为；
2. [语言规范](language-spec.md)；
3. Rust 核心与标准脚本的现行实现；
4. 详细参考手册中的历史说明。

发现冲突时不能仅凭旧实现输出覆盖当前测试。有完整输入、稳定复现且违反现行契约的问题才作为兼容性缺陷处理。

## 允许的改进

兼容方针允许修复确定错误、非终止和状态泄漏；增加资源上限；改善数值表示和错误分类；优化规则分派；新增假设、追踪和宿主接口；在旧入口仍可用时增加信息更完整的新入口。

有意改变可观察结果时，应记录触发条件、旧行为、新行为和理由，并添加回归测试。

## 标准脚本维护

标准脚本保留公开函数和可运行规则，新算法优先放入来源清晰的扩展包。增量维护不要求保留缺陷，也不禁止重构；它要求改动由测试说明，并避免无意破坏无关脚本。

Rust 核心与标准脚本以语言命令为边界。把脚本算法迁入 Rust 前，需要同时考虑可维护性、性能、规则可扩展性和许可；仅因 Rust 能实现同一算法并不足以迁移。

## 参考资料与归属

编程指南、函数参考和算法说明最初来自 Yacas 文档，许可和贡献者信息保留在本目录。这些资料现在是本项目的维护基线，其中的历史功能不自动表示当前产品完整支持。调查行为来源时，仓库内 `oracle` 可作只读参照；正常构建、测试和发布不依赖它。
